# Incident Evidence Ledger: Vibe-Coded Apps and AI Coding Agents (March 2025 – 8 October 2026)

Scope note: this ledger was built from primary sources (vendor posts, researcher write-ups, CVE records, court dockets) wherever one exists, and marks press-only claims as such. It is designed to replace the compressed incident narrative in the original report and to answer the audit's section B request. Confidence labels: **High** = first-party or primary researcher source read directly; **Medium** = reputable press quoting a named party, primary not located; **Low** = secondary/aggregator only or single-user forum report. Dates are the incident date unless stated; "pub." = publication date of the cited source.

Legend for access-capability column: R = read rows; W = insert rows; U = update/PATCH rows; D = delete rows (row-level via PostgREST, *not* DDL); DDL = schema change / DROP; ACCT = unauthorised account creation; SRC = source-code/secret exposure; VOL = volume/instance deletion; CRED = cloud/API credential theft.

---

## Key Question 1: For each incident, what exactly was demonstrated, per the primary source?

### Takeaway
Across twelve core incidents plus six newly surfaced ones, the demonstrated capability was almost always **row-level read/write via a PostgREST or Firebase endpoint using an intentionally public client key**, never DDL `DROP TABLE`. The destructive incidents (Replit/SaaStr, PocketOS, DataTalks.Club, Claude Code #88753) were **agent-plane** failures where the agent held an over-scoped credential, and they are a distinct class from the authorisation failures.

**1. CVE-2025-48757 (Lovable RLS)**
- Discovery: "On March 20th, 2025, we discovered a critical vulnerability in Lovable's implementation of Row Level Security (RLS) policies"; scan "completed on March 21st, identified 303 endpoints across 170 projects (approximately 10.3% of the 1645 analyzed)"; "This script only analyzed homepages" — [Palmer, Statement](https://mattpalmer.io/posts/statement-on-CVE-2025-48757/)
- Key vs policy: "The core issue was not an exposed public API key as we initially thought (Supabase provides public anon keys by design) but the absent RLS configuration." — [Palmer, Statement](https://mattpalmer.io/posts/statement-on-CVE-2025-48757/)
- Write demonstrated 24 May 2025 on a Lovable-employee-maintained site: "removing the authorization header bypassed all access controls... We successfully inserted a new record... including setting `"payment_status": "paid"`, thereby bypassing the Stripe integration." — [Palmer, Statement](https://mattpalmer.io/posts/statement-on-CVE-2025-48757/)
- Palmer's own CVSS: "AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:N... Base Score: 8.26, Temporal Score: 7.58"; "Fixed Versions: None"; "The requests may also be modified to insert, update, or delete data" — [Palmer, CVE page](https://mattpalmer.io/posts/CVE-2025-48757)
- MITRE CNA record: published 2025-05-30; description "An insufficient database Row-Level Security policy in Lovable through 2025-04-15 allows remote unauthenticated attackers to read or write to arbitrary database tables of generated sites. NOTE: this is disputed by the Supplier because each individual customer of the Lovable platform accepts a responsibility over protecting the data of their application."; CWE-863; metrics `cvssV3_1` baseScore 9.3 vector `S:C`; tags `["exclusively-hosted-service","disputed"]`; CISA ADP SSVC: Exploitation "poc", Automatable "yes", Technical Impact "partial" — [MITRE CVE JSON](https://cveawg.mitre.org/api/cve/CVE-2025-48757)

- Independent confirmation of exploitation 14 Apr 2025: "A Palantir engineer independently discovered and publicly tweeted about the same vulnerability, demonstrating active exploitation (e.g., extracting personal debt amounts, home addresses, API keys)" — [Palmer, Statement](https://mattpalmer.io/posts/statement-on-CVE-2025-48757/); tweet referenced in CVE record: [x.com/danialasaria](https://x.com/danialasaria/status/1911862269996118272)

## Key Question 3: Which layer failed in each incident, and what single control would have interrupted the path?

### Takeaway
Four layers account for every incident: (a) generated app authorisation (RLS/RPC), (b) builder-platform authorisation, (c) agent credential reach, (d) organisational publishing defaults. The interrupting control differs by layer and is never "a better prompt".

### Cited Findings (layer attribution grounded in primary wording)

| Incident | Layer | Primary wording supporting attribution | Single interrupting control (inference) |
|---|---|---|---|
| CVE-2025-48757 | App authorisation | "missing or insufficient Row Level Security (RLS) policies"; "despite using the non-sensitive and unprivileged anon key" — [Palmer](https://mattpalmer.io/posts/CVE-2025-48757) | Behavioural anon-role test (SELECT/INSERT/PATCH/DELETE must fail) as a publish gate; or no default grants to `anon` |
| Moltbook | App authorisation | "without RLS policies, this key grants full database access to anyone who has it. In Moltbook's implementation, this critical line of defense was missing" — [Wiz](https://www.wiz.io/blog/exposed-moltbook-database-reveals-millions-of-api-keys) | Same; plus write-path test (write survived two fixes) |

OECD AI Incidents Monitor logged Lovable (20 Apr 2026) and PocketOS (27 Apr 2026) as AI incidents — [OECD Lovable](https://oecd.ai/en/incidents/2026-04-20-b869); [OECD PocketOS](https://oecd.ai/en/incidents/2026-04-27-6153).
- **RedAccess follow-up**: "some of the exposed applications Axios viewed earlier this week were no longer publicly accessible by Wednesday after the companies were notified"; Lovable "started to review and remove these phishing sites" — [Axios](https://www.axios.com/2026/05/07/loveable-replit-vibe-coding-privacy).

### Inferences
- Vendor remediation has consistently targeted *defaults and blast radius* (private-by-default, dev/prod split, soft delete, explicit grants) and not *correctness* of customer authorisation logic, consistent with the original report's conclusion.
- The absence of DPA action is consistent with the lag between breach and enforcement decisions (typically 1–3 years) rather than evidence that no notification occurred.

### Gaps
- No evidence located of any GDPR Article 33 notification by Connected Women in AI, any RedAccess-exposed UK/EU organisation, or Lovable (as Swedish controller) to IMY. Absence of public record is not evidence of absence.
- No SEC, FTC or state AG action on any incident in the ledger was found.

## Key Question 5: Which incidents involved EU-based organisations or EU data subjects?

### Takeaway
EU exposure is documented in at least five incidents: Lovable itself is Stockholm-based (so both the CVE-2025-48757 class and the 2026 regression are failures of an EU-established controller/processor); the April 2026 BOLA exposed a Danish nonprofit's user records; RedAccess verified UK clinical-trial and customer-service exposures plus a Belgian vacation app; Escape found IBANs; UpGuard found a consulate database in France.

### Cited Findings
- Lovable is "the Swedish AI-coding startup" — [Business Insider](https://www.businessinsider.com/lovable-security-access-vibe-coding-projects-risk-2026-4); "Stockholm-based" — [OECD AI Incidents](https://oecd.ai/en/incidents/2026-04-20-b869).
- Lovable BOLA: "Connected Women in AI, a Danish nonprofit... names, job titles, LinkedIn profiles, and Stripe customer IDs, with records linked to individuals at Accenture Denmark and Copenhagen Business School" — [TNW](https://thenextweb.com/news/lovable-vibe-coding-security-crisis-exposed); French legal commentary says Deutsche Telekom customers "seraient concernés" (unverified, conditional) — [le-droit.fr](https://www.le-droit.fr/blog/fuite-donnees-lovable-vibe-coding).
- RedAccess (Axios-verified): "An internal application for a health company that details active clinical trials across the U.K."; "Full, unredacted customer service conversations for a cabinet supplier in the U.K."; "A personal app... to help plan a couple's vacation in Belgium" — [Axios](https://www.axios.com/2026/05/07/loveable-replit-vibe-coding-privacy); RedAccess PDF notes exposures "Subject to specific regulatory regimes — HIPAA, GDPR, the Data Protection Act" — [RedAccess PDF](https://info.redaccess.io/hubfs/1627The%20Shadow%20Builders%20Inside%20Your%20Organization%20%E2%80%94%20Red%20Access%20Research%20(1).pdf).
- Escape: verified exposure of "bank account name and IBAN" plus plaintext password via anon GET; 175 PII instances "including medical records, IBANs" — [Escape PDF](https://26857953.fs1.hubspotusercontent-eu1.net/hubfs/26857953/State-Security-Vibe%20Coded%20Apps%20Report%202025%20Escape.pdf). Escape is a French company (Paris) per its report authorship; IBAN presence implies EU/SEPA data subjects but country is not stated.
- UpGuard: "One of the databases belonged to an African government's consulate in France" — [TechCrunch](https://techcrunch.com/2026/09/25/some-supabase-customers-are-publicly-exposing-reams-of-peoples-data-to-the-web/); "25,000 users with PII and physical addresses... belong to a vulnerable population... which emergency housing location individuals are currently residing" — [UpGuard](https://www.upguard.com/blog/everything-everywhere-systemic-data-exposure-in-supabase-apps).
- CVE-2025-48757 has an ENISA EU Vulnerability Database entry EUVD-2025-16441 — [Tenable references](https://www.tenable.com/cve/CVE-2025-48757).
- Moltbook: 35,000 emails and 17,000 human owners; no geography published — [Wiz](https://www.wiz.io/blog/exposed-moltbook-database-reveals-millions-of-api-keys).

### Inferences
- For EU organisations the two Lovable incidents are the most consequential: Lovable is an EU-established processor (and, per its DPA, an independent controller for service/log data), so IMY (Sweden) would be lead supervisory authority for any platform-level breach; the Connected Women in AI exposure is a textbook case where a Danish controller would have to assess Article 33/34 obligations arising from a processor's platform regression.
- RedAccess's UK examples fall under UK GDPR/ICO rather than EU GDPR.

### Gaps
- No public breach notification, DPA complaint or supervisory statement was found for any EU-affected incident.
- Geographic distribution of UpGuard's 16,326 databases is not published beyond "majority... in the United States".
- Whether any of Symbiotic's or Reeve's affected apps are EU-controlled is not published.
